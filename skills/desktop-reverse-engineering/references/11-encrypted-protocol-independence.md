# 11 · 从原生加密链路到独立调用

适用：页面或插件版本变化阻断功能、网络仅看到加密隧道、希望从客户端调用迁移到独立请求。普通 HTTP/JSON 不必经过全部阶段。

## 先把“独立”拆成可验证的依赖

分别记录 **材料获取、每次请求计算、发送、响应解析、材料刷新** 五个阶段。每阶段列出 UI、页面运行时、目标进程、后台服务、厂商库及构建、会话/设备状态。

- 不执行页面脚本，不等于不依赖目标主进程。
- 不调用目标进程，不等于已移除官方动态库或会话材料依赖。
- 请求时无需客户端，不证明登录/刷新也无需客户端。
- 客户端仍在运行时完成独立请求，可报告“本次调用未使用目标进程”；没有授权停进程实验，不标为已验证“客户端关闭后仍可用”。

拆分协议层与平台适配器：通用部分处理边界、序列化、认证、状态和结果；平台配置承载模块哈希、架构、入口位置、ABI、路由/场景枚举及错误映射。不要把一个构建的地址或某平台错误码写成通用规则。

## 1. 锁定真实入口，保留小而完整的基线

同名搜索、消息或列表功能可能有不同的页面入口、场景枚举、内部命令和外层路由。记录完整路径：

```text
用户入口 → 页面/IPC/本地业务调用 → 内层命令与场景
        → 序列化 → 压缩 → 业务加密/包头 → 传输封装 → 网络
```

给一次动作分配采样窗口、进程实例、线程/连接/请求关联标识。只靠相近时间或相似长度不能绑定请求与响应。搜索建议、预加载、心跳也可能用同一加密函数；先打开目标页面，再为明确动作短时采样，记录上限与丢弃数。

原始字节写入受控研究目录；报告只记录长度、哈希、数值错误码和脱敏关联信息。摘要丢失字节时不可作为重建输入。模板见 [采样记录](../templates/capture-session.md)。

## 2. 先证明边界，再解释内容

| 边界 | 必须确认 | 常见误判 |
|---|---|---|
| 调用参数 | 入口/出口、ABI、指针、长度来源、初始化时机 | 把容量或分配长度当有效数据长度 |
| 异步接收 | 完成通知的实际字节数、操作实例/代次、缓冲区寿命 | 在提交时读取尚未完成的接收缓冲区 |
| TCP/HTTP | 分片、合并、部分写、完整长度、尾随数据 | 把一次 socket 回调当一个完整报文 |
| 私有帧 | 长度是否含头、字节序、可选前缀、版本分支 | 固定偏移跳过未知字节 |
| AEAD | 请求/响应密钥、IV、tag、AAD、密文排列 | 默认两方向同密钥或 AAD 为空 |
| 压缩 | 算法、级别、实际消耗字节、输出上限 | 解压成功就忽略未消费尾部 |
| Protobuf/JSON | 字段类型、嵌套信封、显式零值、缺省语义 | 缺失返回码默认成功、字符串数字随意转换 |

没有完整边界的样本先标为不完整；不要用“多读固定几十字节”补齐。异步完成的失败状态、缓冲区复用和跨窗口旧回调必须单独处理。插件收到消息或 socket 提交成功不等于服务端接受。

## 3. 沿一条业务调用链定位，不先反编译整个程序

优先使用已有请求边界、路由字符串、日志、序列化器或加解密包装函数，追踪必要的调用者/被调用者。目标是恢复输入输出契约，不是逐函数翻译程序。

- 固定模块实际路径、文件哈希、架构和加载模块大小；执行插桩前核对入口指令与函数边界。ASLR 下记录 RVA 与模块基址，不能直接重用绝对地址。
- 对调用约定、寄存器/栈参数、对象归属、线程要求和返回值语义逐项验证。静态候选和运行时实际分支分别记录。
- 入口观测足以读取已初始化输入时，优先不用 onLeave；需要输出则说明完成语义和生命周期成本。入口无输出证据时，不能宣称原生函数成功。
- 反汇编遇到数据、跳表或中间指令时，不凭连续可反汇编字节确认函数入口；结合 PE 异常表、符号、调用引用等适用证据。
- 模块变更、参数形状不符或未知版本时停止当前适配器，不能带旧偏移试调用。

## 4. 离线闭环后才发新请求

按实际协议顺序恢复，每层保留可重放输入/输出和哈希：

1. 从明确参数重建序列化结果；检验字符编码、未知字段保留策略和字段类型。
2. 使用采样时的随机量、压缩配置和密钥重建已知密文，与原报文逐字节匹配。
3. 还原包头、长度、签名、校验、序号和完整传输封装；不能只比较前缀或长度。
4. 对响应独立完成认证、解压、结构解析、业务码和参数回显校验。
5. 增加针对实际边界的失败样本：截断、篡改 tag、溢出长度、未知头格式、缺失成功码。合成测试只证明本地行为。

旧随机量仅用于离线重建。新请求按目标契约生成新的 nonce/IV、请求标识和序号，不重放一次性密文。严格匹配对照时可同时固定多个已捕获的随机量，但实验变量与固定条件必须写清。

## 5. 必须保留厂商库时，缩小并声明依赖

能复用稳定独立库时，不必为了“纯协议”而无限追算法。先明确架构、导出名称/序号、ABI、初始化与回调、输入编码、长度和终止符、环境/线程依赖。

例如摘要函数需要确认输入是原始摘要字节还是十六进制文本、大小写、是否含终止零、长度单位和参与计算的密文范围；不能凭函数名推断。

- 准备已知输入输出向量，在计算新值前验证初始化和已知答案；已知答案失败不能带猜测值继续网络请求。
- 适用时将库放在独立辅助进程，只传必要的非秘密输入；明确网络、文件和令牌权限，并验证实际限制。Windows 的 AppContainer/Job 是一种实现，不是跨平台默认前置。
- 同时固定库、辅助程序、源码/构建参数和向量的哈希；改变其中任一项需重验相关契约。
- 无回调不等于初始化失败，回调出现也不等于业务成功。不要无目的读取回调内的敏感载荷。
- 超时后要确认进程退出和隔离资源清理。未完成时记录 unknown，而不是悄悄再开一个辅助进程。

## 6. 真实验证使用新参数和有限请求预算

离线准备默认不发请求；执行时记录发送意图、请求数量、阶段和最终结果。请求预算按操作风险及用户范围设定，不能把某次案例的“两页”固化为所有研究的规则。

一次新参数请求成功后，再验证有状态续请求：

- 沿用上一响应的真实游标、offset、搜索/事务 ID、cookies 或 continuation token。不要按页大小猜 offset。
- 保留协议要求不变的会话信息；更新协议要求每次变化的 request ID，并保持顶层与嵌套字段一致。
- 包头 cookie 与业务分页 cookie 分开处理；是否为空时更新，必须来自该协议证据。
- 校验查询词/目标对象回显、页码、全部必要成功码、游标推进或明确结束语义。
- 在去重前统计原始条目。按稳定业务标识检查页内重复、跨页交集、合并唯一数；多个标识同时存在时可分别交叉核对，标题相同本身不是同一对象的证明。
- 保存服务端错误，不把 HTTP 200 或通过传输认证当作功能成功。未知结果不自动重试，先查已保存的响应和可用对账路径。

首屏和第二页成功只覆盖该版本、会话与输入；未测试的耗尽、并发、长跑、重登刷新和停客户端实验分别保留为 UNTESTED。

## 7. 小错误包与材料失效

完整、已认证但很短的回包可能只有错误头。先查原生解析器的版本/可选前缀分支，再确定长度、字节序、有符号性与错误字段位置；本地“不支持格式”不是服务端错误码。

把数值追到同一构建的消费者、日志或状态分支，并记录证据地址。只有该映射成立时才将它归类为会话失效、参数错误等。错误头无正文时，不强行做正文解密或解压。

传输密钥仍能认证回包，与业务会话已失效可以同时成立。某个业务错误确认“会话失效”，通常不能单独区分自然过期、退出、撤销或被替换；更不能推出所有材料均失效。刷新与旧失败样本分开保存，旧审计保持不变，新增审计记录解释。详见 [06](06-credentials-session.md)。
