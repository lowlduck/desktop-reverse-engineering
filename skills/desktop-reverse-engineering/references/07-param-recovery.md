# 07 · 参数还原：前端、信封与错误码

> 参数不知道时，**不要猜，去读前端**。猜参数是最贵的试错方式。

## 前端代码三条获取路径

| 路径 | 何时用 | 做法 | 成本 |
|---|---|---|---|
| ① 本地资源目录 | 命令行有 `--*-local-root-path` / `--user-data-dir` | 直接 grep 本地 JS | 分钟 |
| ② **用凭据拉远端页面** | 本地没有（服务端渲染 / 资源不落地） | 带客户端 UA 下 `index.html` 与 bundle 落盘再静态读 | 10 分钟 |
| ③ CDP | 需要运行时信息（闭包、动态参数、DOM） | `Runtime.evaluate` 调页面函数 / 包装 fetch | 需先能开 DevTools |

②最容易漏：**只要有登录态，前端代码就是可以静态下载的资产**，不必先解决动态调试。
带 UA / Referer / Origin，否则容易拿到拦截页或 403。

```text
GET 页面 → 解析 <script src> → 逐个下载到 js/ → grep 端点与关键字
本地 grep 零命中 ≠ 功能不存在，可能这个端点的 bundle 只在远端版本里
```

## 巨型单行 bundle 怎么读

压缩成一行的 bundle，`Select-String` 给不出有效上下文。做法：

```python
src = open('bundle.js', encoding='utf-8', errors='replace').read()
i, KEY = 0, '/ENDPOINT'
while (i := src.find(KEY, i)) != -1:
    print(src[max(0, i-300): i+300].replace('\n', ' '), '\n---')
    i += len(KEY)
```

**落盘 + 切片**，不要把几 MB 的 JS 整体读进上下文。

## 请求信封：body 形状不要猜

同一端点，平铺 body 全错、套上信封全对：

```text
❌ {"page":1,"size":5,"offset":0}                  → 参数错误（试了 7 种组合全错）
✅ {"data":{"page":1,"size":5,"offset":0},"client":1} → 成功
```

定位手法（可复用）：

1. bundle 里搜端点字符串 → 找到调用点：`this.request(path, {data: e, client: r.WEB})`
2. 再搜传输层实现：`J = function(e){ return function(t, n, r){ var p = merge(defaultData, n); ... } }`
   → **第二个参数整体就是 body**，所以 `{data, client}` 被原样发出去
3. 枚举值也从代码读：`e[e.WEB=1]="WEB"` → `client=1`，不要试 `"web"` / `2` / `"1"`

**通用规律**：凡是有「客户端类型 / 端类型」的接口，几乎都有这层包装。先假设存在信封再验证，比逐字段试快一个数量级。
反向也成立：拿到的参考请求体如果字段名比文档少一层，先怀疑信封丢了吗。

## 错误码当坐标，不要当失败信号

```
A 类：参数校验层（缺字段 / 类型错 / 形状错）
B 类：业务层（字段合规但业务拒绝：无权限、对象不存在、前置条件不满足）
C 类：鉴权层（会话失效 / 未登录）
D 类：成功

从 A 走到 B = 形状已经对了，剩下只是取值/对象问题 —— 这是重大进展。
```

**一次只改一个变量，看错误码是否「升级」：**

| 你改了什么 | 错误码变化 | 说明 |
|---|---|---|
| 平铺 body → 套信封 | A → D | 形状是主因，一次解决 |
| 某字段 字符串 → 对象 | A（提示变具体） | 类型过了但内容不对 |
| 换 ID 的形态（宽度/来源） | A → B | **形状对了**，别再改 body，去查 ID 从哪来 |
| 加/去非必需头 | 无变化 | 该头非必需，别耗时间 |

配套动作：**把错误码词典写进研究记录**（`成功码 / 参数错 / 系统错 / 会话失效 / 限流`）。有了词典，下一次同类错误能自己读出「我在哪一层」。

## 字段与序列化

逐字段记录：名称、类型、编码、长度、范围、必选/默认、来源、是否每次变化、相互依赖。

- 空值 / 缺字段 / 空字符串三者含义可能不同。
- ID、时间戳、计数器不要猜成任意常量——它们常有形态约束（前缀、位数、来源），错了会停在 B 类。
- 覆盖字符集、Unicode、浮点与整数宽度、字节序、压缩、长度定义、最大报文。
- 固定抓包只是样本，不是通用生成器。
- 签名/校验是契约依赖：必须有测试向量或正常会话接口支持，不能从一次重放成功推断可长期复用。

## 签名策略优先级

```
复用（不绑 body 的签名直接沿用）
  > 调内部函数让它自己算（CDP / T2）
  > 逆算法
  > 模拟浏览器环境
```

配套三种实测判据：签名不绑 body/时间 → 可复用；页面自动加（拦截器）→ 在页面上下文发；服务端根本不校验 → 先试不带（确认后再决定要不要维护它）。
