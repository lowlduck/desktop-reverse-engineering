# 13 · 脱敏案例：从页面依赖到两页独立请求

此处保留 2026-10-23 至 2026-10-26 的研究过程、反例与验收范围，不包含产品端点、模块地址、真实标识、密钥、票据、DLL 或原始抓包。它是方法来源，不是任意桌面应用的已验证适配器。

## 问题与路径

目标功能由桌面应用的嵌入式页面发起，页面插件升级会改变原有调用入口。研究目标是复现关键词搜索及翻页，并将每次请求移出页面运行时。

1. **入口核对**：历史材料与当前入口属于不同场景/命令。历史样本用于理解传输和编码，未直接当作当前业务契约。
2. **采样边界**：区分 native buffer 的有效输入长度与容量、异步提交与实际完成长度；保存原字节而非终端中的长文本摘要。
3. **原生链路**：沿业务封包/解包函数追到压缩、AEAD 包装、包头和传输层。固定模块构建与哈希，只定位必要函数。
4. **离线重建**：用已捕获的随机量还原旧请求，从业务正文到外层封包做逐字节对照；请求和响应使用不同业务密钥。
5. **保留最小原生依赖**：某个校验值继续由官方库计算。最初对摘要文本大小写的假设导致已知答案失败；回溯调用链后纠正。新值仅在初始化及两个已知向量通过后计算，辅助进程隔离并验证清理。
6. **独立请求**：新关键词首屏及真实游标续页成功。调用未执行页面代码、未调用目标进程，但仍使用已登录会话材料和固定官方库。

## 失败样本带来的改进

### 短回包不能当作未知密文丢弃

隔日使用旧材料的一次请求得到 HTTP 200，传输认证通过，应用载荷只有 32 字节。原解析器只接受扩展头，因此报“不支持格式”。

没有重试或刷新，而是离线对照同构建原生解析器，发现基础头分支；解出负数头部返回码，并从原生消费者的专门分支和日志确定其含义为“会话超时”。整包都是头部，无搜索正文。

**结论边界**：可确认业务会话失效，不能仅凭该包区分自然到期、退出、撤销或会话替换，也不能认定所有传输材料都过期。错误数字及其意义属于该构建，不作为通用错误码表发布。

### 材料刷新与业务契约分开

用户确认已退出并重新登录后，采集得到的新业务收发密钥、传输材料及票据均不同于旧值。页面打开及输入建议消耗了首轮采样预算，第二轮才保留到目标请求；缺样本没有被描述成“功能不存在”。

新的页面入口仍与原独立请求的场景不同。保留新请求的外层认证信封，仅将内层请求替换为此前已真实验证的目标场景契约，并使用本轮观察到的会话标识。离线检查其他外层字段保持后，仅发起一次新关键词请求，确认服务端接受。**这种组合是本案例的已验证结果，不是可任意混用不同场景或会话材料的规则。**

### 清理成功必须有完成证据

较早的一轮多控制器采集中，业务成功后目标进程崩溃；部分清理超时，却因状态属性提前变化被记录为完成。审计确认了控制器并发清理缺陷，但未确认崩溃根因。

后续合并为单 session/单脚本，控制器保留未完成 future，逐项等待 pause、stop、unload、detach。两轮采集均记录到主动 detach、全部操作完成且无时间重叠，目标随后仍存活。该结果不被扩大为长期稳定性证明。

## 最终验收快照

| 维度 | 已验证 | 未据此宣称 |
|---|---|---|
| 新关键词 | 首屏 12 条、全部必要返回码显式成功 | 任意关键词/所有场景兼容 |
| 真实续页 | 沿用返回游标，Offset 0 → 12 → 24，第二页页码正确 | 固定页大小、已取尽全部结果 |
| 去重 | 两页各 12 条，页内及跨页重复 0，合计 24 个唯一对象；多个标识交叉核对 | 标题不同就一定是不同对象 |
| 认证 | 传输与业务 AEAD 验证、正文与参数回显匹配 | 完整实现了传输协议的所有握手语义 |
| 依赖 | 每次请求不经过嵌入式页面或目标进程调用 | 材料获取/刷新无 UI、无厂商库、跨版本自动适配 |
| 材料 | 新会话材料可用，旧材料收到会话超时 | 固定有效期、自动续期机制已完成 |
| 操作范围 | 首屏与后续单次第二页分别受限；无隐式重试 | 多账号、并发、长跑、关闭客户端后可用 |
