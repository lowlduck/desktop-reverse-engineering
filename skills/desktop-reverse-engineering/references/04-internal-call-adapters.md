# 04 · T2 内部函数适配

T2 通过导出函数、业务对象方法、本地桥接或调试接口调用客户端逻辑。

## 核心原则：调而不破

```
算法被保护 → 不能「逆算法」
        ↓
但可以「直接调用它」：
  · 页面函数（CDP）
  · 导出函数（注入后调用）
  · hook 它的调用点，让客户端自己算
        ↓
不需要知道算法是什么，只需要知道「怎么让它算」
```

实测对照：三个签名中一个在明文 JS 里直接逆出、两个改为复用/页面内调用解决——**没有一个需要破壳**。
所以当「必须静态理解算法」这个前提不成立时，T2 通常是更快的路。

反面同样成立：取不到 `this` 指针、签名与 ABI 读不出来时，**不要硬猜**。优先退回「hook 调用点」——在既有业务路径上加一层观测，比自己构造调用更快出结果。

## 原生函数检查表

- **身份**：应用版本、模块哈希、架构、运行时/编译器 ABI、模块加载实例必须匹配。
- **地址**：优先有契约的导出或符号。记录模块相对地址及版本绑定，运行时重新定位；ASLR 后不可复用旧绝对地址。地址命中只是候选，仍需语义验证；未知版本或多候选停止调用。
- **ABI**：参数顺序、宽度、有符号性、调用约定、栈对齐、返回值、结构体布局/packing、可变参数、异常边界。同名导出不证明 ABI 一致。
- **对象**：`this` 指针来源、类型与有效期、构造/初始化完成时机、所有权/引用计数、失效信号。不要用历史指针跨重启。
- **内存**：字符串编码、缓冲区长度、输入是否复制、返回对象由谁释放、分配器匹配。跨模块 C++ 容器尤其要验证运行时兼容。
- **线程**：线程亲和性、事件循环、锁顺序、重入与并发。业务函数即使要求 UI 所在线程执行，也应通过任务调度直接调用，不通过点击或 UI 事件触发。
- **异步**：回调线程、回调存活期、完成/取消竞态、超时后是否仍执行、卸载前等待在途调用结束。
- **重启**：模块卸载、会话切换、窗口/业务对象销毁后使句柄失效，再初始化并检测能力。

## JS / CDP / managed runtime

记录页面/进程/执行上下文的身份、业务对象初始化条件、函数版本与参数 schema。页面刷新、renderer 重启、导航和 GC 会使引用失效；重新发现上下文，而非长期缓存对象 ID。正确等待 Promise/回调，区分异常与业务失败。

`Object.keys(window)` 之类的枚举常能直接找到可用业务函数（如某个 `socketUtil` 风格的发送封装），先枚举再决定要不要自己拼协议。

直接调用业务方法属于 T2；调用 `click()`、派发 DOM/UI 事件、模拟快捷键，即使通过 CDP 执行仍是 UI 自动化，不作为交付路径。

## 适配器边界

建议状态机：`UNINITIALIZED → READY → BUSY → READY`；会话失效 → `AUTH_REQUIRED`，上下文失效 → `REINITIALIZE_REQUIRED`，版本不匹配 → `UNSUPPORTED_VERSION`。状态迁移要具备锁或其它并发控制，不能把异常后的对象默认视为可继续使用。

对外只暴露参数化业务契约，内部隔离各版本适配器。启动时执行无副作用探针校验 capability 与版本；桥接失败返回结构化错误，不静默退回 UI 自动化。

## 版本变更

版本支持以「应用 / 模块 / 架构 / 运行时 / 适配器版本」组合登记。每次升级重新核对地址、ABI、对象与上下文生命周期、返回语义及并发行为。

底层算法不变并不能保护上层函数布局；也不要预设「函数签名很少变」——按实测记录适配工时、缺陷与回归覆盖，不给 T2 固定维护等级。
