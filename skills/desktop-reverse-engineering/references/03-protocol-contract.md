# 03 · 协议与功能契约

## 从事件走向接口

定义 `invoke(FEATURE, parameters, context, deadline, operation_id)` 的语义，实际语言/传输由工程选择。`context` 显式承载会话及能力，不通过全局共享状态隐式切换身份。

概念结果示例（仅占位，不是现成 API）：

```json
{
  "operation_id": "OPERATION_ID",
  "status": "pending",
  "result": null,
  "error": null,
  "retry_policy": "reconcile_first"
}
```

状态至少区分：`succeeded`、`failed`、`pending`、`unknown`。`unknown` 是“可能已执行但结果未确认”，不是可随意重试的失败。

## 参数还原与验证

逐字段记录名称、类型、编码、长度、范围、必选/默认、来源、是否每次变化、相互依赖。用多组输入对照静态构造逻辑与运行结果。空值、缺字段、空字符串的含义可能不同。ID、时间戳、计数器不要猜测为任意常量。

序列化验证要涵盖字符集、Unicode、浮点和整数宽度、字节序、压缩、长度定义与最大报文；固定抓包只作样本，不作为通用生成器。校验或签名是契约依赖，必须有测试向量/正常会话接口支持，不从一次重放成功推断可长期复用。

## 按传输补全

- **HTTP**：方法及路由模板、header 的必要性、Content-Type、重定向、超时、分页、限流和业务错误；服务受理与最终完成分开。
- **WebSocket**：握手及子协议、文本/二进制消息、消息内分片、关联 ID、订阅 ACK、心跳、重连后恢复订阅与游标。不要混淆协议帧和业务事件。
- **TCP**：明确帧头、长度包含范围、字节序、类型字段；增量解析部分读取与多帧合并，限制帧长/缓存大小；处理部分写、半关闭、背压与请求关联。
- **UDP**：数据报上限、截断、序号、去重窗口、乱序、丢包、重组超时；网络层不保证交付，更不保证业务 exactly-once。
- **IPC/RPC**：端点解析、访问控制、消息边界、同步/异步契约、对端退出、句柄重开；共享内存还需版本布局、内存可见性与同步协议。
- **文件/数据库**：优先只读测试副本；明确事务、锁、原子性、schema 版本。写入缓存未必触发业务操作，避免把缓存编辑包装成功能接口。

## 认证与状态

通过宿主支持的登录/会话提供方接收 `AUTH_CONTEXT`，明确有效期、刷新、撤销和权限变更。不要在接口内部悄悄提取系统或其他应用凭据。日志使用脱敏类别与关联 ID，禁止输出凭据值。

会话失效进入 `AUTH_REQUIRED`；支持的刷新流程可以有限次数尝试，必须避免多个调用同时刷新。需要交互登录时暂停相关操作并报告恢复前置条件，不承诺自动绕过。参数化不意味着跨身份复制会话或对象标识。

## T1 独立性试验

记录目标客户端、辅助进程、后台服务依赖；在可控测试环境停止需排除的组件，再验证冷启动、会话恢复、功能完成。残存本地代理或客户端计算服务仍属依赖，报告实际形态。T1 不自带并发能力，仍须测服务限额、资源占用及每会话约束。
