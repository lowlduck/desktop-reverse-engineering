# 03 · 协议与功能契约

## 从事件走向接口

定义 `invoke(FEATURE, parameters, context, deadline, operation_id)` 的语义，实际语言/传输由工程选择。`context` 显式承载会话与能力，不通过全局共享状态隐式切换身份。

```json
{
  "operation_id": "OPERATION_ID",
  "status": "pending",
  "result": null,
  "error": null,
  "retry_policy": "reconcile_first"
}
```

状态至少区分 `succeeded` / `failed` / `pending` / `unknown`。`unknown` 是「可能已执行但结果未确认」，不是可随意重试的失败。

## 按传输补全

- **HTTP**：方法及路由模板、header 必要性、Content-Type、重定向、超时、分页、限流、业务错误码；受理与最终完成分开。注意**请求信封**（见 [07](07-param-recovery.md)）和**端类型枚举**。
- **WebSocket**：握手与子协议、文本/二进制、消息内分片、关联 ID、订阅 ACK、心跳、重连后恢复订阅与游标。不要混淆协议帧与业务事件。
- **TCP**：帧头、长度包含范围、字节序、类型字段；增量解析部分读取与多帧合并；限制帧长/缓存；处理部分写、半关闭、背压、请求关联。
- **UDP**：数据报上限、截断、序号、去重窗口、乱序、丢包、重组超时。网络层不保证交付，更不保证业务 exactly-once。
- **IPC/RPC**：端点解析、访问控制、消息边界、同步/异步契约、对端退出、句柄重开；共享内存还需版本布局、内存可见性、同步协议。
- **文件/数据库**：优先只读测试副本；明确事务、锁、原子性、schema 版本。写入缓存未必触发业务操作，别把「编辑缓存」包装成功能接口。

## 长连接落地五步（实战路径）

> 桌面 IM 类应用**文本常走长连接，HTTP 只用于卡片/文件**。
> 判断信号：HTTP 的 send 端点怎么调都停在 A/B 类错误，且二进制字符串表里没有「按目标 ID 发文本」的端点。

```text
① 找取票端点：搜 /token / getToken / auth → 通常返回 {token, use_ip}
② 拼连接 URL（代码里能直接读到）：
   wss://HOST/?access_token=<token>&role=<角色>&client=<端类型>&version=<build>
③ 握手带上 Cookie + 客户端 UA + Origin（缺一可能被拒或被判为异常端）
④ 帧结构从代码抄：
   {"cmd":"<动作>","request_id":N,"message":{...},"random":"<签名>"}
   · request_id 是关联响应的关键 → 用随机数，比「看谁先回来」可靠
   · 签名算法一般在 bundle 里明文（拼接顺序 + 硬编码盐）
⑤ 用 request_id 匹配响应；再回读列表/历史确认真的生效（双证据）
```

纪律：用完立刻 `close()`，不常驻、不轮询。同账号第二条长连接**很可能与客户端互踢**，这是掉线的高危嫌疑之一（见 [06](06-credentials-session.md)）。

## 参数与序列化校验

逐字段记录名称、类型、编码、长度、范围、必选/默认、来源、是否每次变化、相互依赖。用多组输入对照静态构造逻辑与运行结果。空值、缺字段、空字符串含义可能不同；ID/时间戳/计数器不要猜为任意常量。

序列化验证要覆盖字符集、Unicode、浮点与整数宽度、字节序、压缩、长度定义与最大报文。固定抓包只作样本，不作为通用生成器。校验或签名属于契约依赖，必须有测试向量或正常会话接口支持。

## 认证与状态

通过宿主支持的登录/会话提供方接收 `AUTH_CONTEXT`，明确有效期、刷新、撤销与权限变更。日志使用脱敏类别与关联 ID，不输出凭据值。

会话失效进入 `AUTH_REQUIRED`；支持的刷新流程可有限次尝试，且必须避免多个调用同时刷新。需要交互登录时暂停相关操作并报告恢复前置。

## T1 独立性试验

独立请求的分层重建与真实游标验证见 [11](11-encrypted-protocol-independence.md)。原生多层加密并不自动限定为 T2；可分别评估纯字节重建、独立官方库计算、进程内调用的最小依赖。

记录材料获取/刷新、计算、发送、解析各阶段的目标客户端、辅助进程、后台服务与库依赖；仅在授权的可控测试环境停掉需排除的组件，再验证冷启动、会话恢复、功能完成。没有停进程实验时，报告“调用未使用目标进程”的已证范围。残存的本地代理或客户端计算服务仍属依赖。

T1 不自带并发能力：仍要测服务限额、资源占用、每会话约束。
