# 08 · 上下文预算与研究记录

> 逆向任务的 token 消耗 95% 来自工具输出。不管理它，两小时后必然被压缩，
> 压缩后 AI 会「忘记」试过什么 → 重复劳动 → 预算二次烧掉。

## 铁律：大输出落盘，只读切片

| 场景 | ❌ 错误做法 | ✅ 正确做法 |
|---|---|---|
| 1.4 万行明文日志 | 整读进上下文 | `grep 关键词` → 读前后 60 行 |
| 3.7 MB 打包 JS | 整体读 | 落盘 → `str.find()` 打印 ±300 字符 |
| 抓包 JSON | 贴全文 | 只引用「路径 + 关键 3 行 + 行号」 |
| 同一日志 | 读第二次 | 读完立刻把结论写进记录，不再回读 |

```powershell
# 只捞关键行，不整读
Select-String -Path .\capture.log -Pattern 'request parameter|ENDPOINT|error_code' |
    Select-Object -First 40 | ForEach-Object { "$($_.LineNumber): $($_.Line)" }
```

```powershell
# 二进制里搜字符串（Select-String 没有 -Encoding Byte，用 rg -a）
rg -a -o "/[a-zA-Z0-9_/]{6,60}" .\TARGET.dll | Sort-Object -Unique | Select-Object -First 80
```

## 只维护一个主文档

```
✅ 一个 RESEARCH_PROGRESS.md，永远是最新的
❌ 散成 10 个 md —— 压缩后找不到，等于没记
```

结构照 [研究记录模板](../templates/research-record.md)。四个区块，缺一不可：

1. **已确认结论**（不要重复验证）——每条带【证据】：实测输出 / 错误码 / 日志行号
2. **已排除的方案**（不要再试）——带错误码！
3. **可用工具**——装在哪、怎么跑、日志路径、怎么恢复
4. **下一步待办**——下一个最小可证伪实验

## 写入时机（不等阶段结束）

| 触发 | 立刻做什么 |
|---|---|
| 拿到一条可验证结论 | 追加到「已确认」+ 打标签 |
| 一条路线失败 | 追加到「已排除」（**带错误码/现象**） |
| 成功部署一个工具 | 追加到「可用工具」 |
| 计划变更 / 触及时间盒 | 更新「下一步」 |

## 失败记录的最低标准

```
❌ "Frida 失败"
✅ "Frida attach → ProcessNotRespondingError (pid 126680)；
   该目标有 反调试+代码虚拟化 组合，attach 阶段即被踢出"
```

差别不在详细程度，在于**下次能不能据此判断「要不要再试一次」**。

## 压缩后的恢复动作

```
1. 读「已确认结论」→ 确认已知边界
2. 读「已排除方案」→ 避免重试
3. 读「下一步」→ 继续
4. 不要重新验证已有结论
```

## 给 AI 的开工自检

```
□ 我读研究记录了吗？
□ 我要做的这件事，在「已排除」里吗？
□ 我要验证的东西，在「已确认」里吗？
□ 我的目标层级定好了吗（T0/T1/T2）？
□ 这次的大输出我会落盘吗？
```

## 反面案例（真实踩过）

| 错误 | 后果 |
|---|---|
| 结论散落在 10+ 个 md | 压缩后找不到，重复查 |
| 只记「代理失败」，没记「试了哪 5 种」 | 又试了一遍 |
| 把猜测写成结论，没打标签 | 后续基于错误前提推进 |
| 没记「某注入方式会递归爆炸」 | 第二次差点又用 |
