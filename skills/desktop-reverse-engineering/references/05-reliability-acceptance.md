# 05 · 可靠性与验收

## 验收按约定范围进行

「稳定、高复用」不是支持所有消息类型，也不是保证未来所有版本可用。列明支持的平台、版本、操作、参数范围、客户端依赖、初始化与登录前置。任何未执行项标记 UNTESTED。

| 项目 | 要求与证据 |
|---|---|
| 功能结果 | 参数化重复调用，独立查询或业务回执确认效果；受理成功不等于完成 |
| 参数边界 | 正常、空值、长度边界、非法类型、不同目标；记录预期与实际 |
| 状态隔离 | 多会话或实例不串身份、对象、回调；有状态接口明确生命周期 |
| 中断恢复 | 断连、服务重启、客户端重启、上下文失效后行为可预测 |
| 认证失效 | 返回 AUTH_REQUIRED 或执行明确支持的刷新流程，不无限刷新 |
| 并发与容量 | 约定负载下测延迟、错误率、资源、背压，不假定无限并发 |
| 长期运行 | 按业务设持续时间与调用量，测内存、句柄、连接、队列趋势 |
| 版本回归 | 已支持版本逐项验证；未知版本停止不兼容调用并报告 |
| 无 UI 依赖 | 最终调用链不使用点击、截图识别、键鼠或 DOM 事件模拟 |
| 清理 | 关闭连接、释放对象、撤销观测改动；保留原样本与回滚说明 |

## 重试与副作用

给每次业务操作分配 `operation_id`，但本地 ID 本身不代表服务端支持去重。区分「未发送 / 已发送待确认 / 明确失败 / 成功」。超时或连接中断后的结果是 `unknown`：先查询或对账。没有可靠幂等/去重时，副作用操作**不自动重发**。

可安全重试的操作：设总 deadline、次数上限、指数退避 + jitter，遵循服务端限流提示。失败恢复不得无限递归。取消请求不保证远端操作取消，仍需确认结果。

**单号生成与时间戳**：本地时间戳参与签名或幂等键时，先确认服务端对时钟漂移的容忍度，再决定是否本地生成。

## 交付形态（把「研究」变成「别人能用的东西」）

```text
□ 交互式入口 + 明确提示（序号/ID 双输入都接受，别只认一种）
□ 危险动作有硬开关：默认只预览，--execute 才真发；发完打印结果码
□ 一键自测（--selftest）：不需要懂参数，跑一条命令就知道环境通不通
□ 错误友好化：不抛 traceback；错误码翻译成人话 + 给出下一步动作
□ 不落盘敏感凭据：每次现取、用完即弃（也顺带避免缓存到过期值）
□ 防闪退：双击场景窗口必须留住（.bat + pause / input）
□ 请求头三件套对齐客户端：UA / Referer / Origin
□ 一份 .txt 使用说明（编码正确）+ 一份 md 研究记录（结论 + 证据 + 已排除）
```

## 清理与回滚

改任何文件之前先记 manifest，交付时一起给：

```powershell
# 变更前
$f = '<PATH>'
@{
  path   = $f
  sha256 = (Get-FileHash $f -Algorithm SHA256).Hash
  backup = "$f.bak_$(Get-Date -Format yyyyMMdd_HHmmss)"
  time   = (Get-Date).ToString('s')
} | ConvertTo-Json | Add-Content manifest.json
Copy-Item $f "$($_.backup)"
```

清理清单：恢复被替换文件、删除测试残留（注册表/hosts/代理/环境变量）、关闭常驻进程、确认目标程序仍正常、保留原样本与派生产物分离。
