# 05 · 可靠性与验收

## 验收按约定范围进行

稳定、高复用不是支持所有消息类型，也不是保证未来所有版本可用。列明支持的平台、版本、操作、参数范围、客户端依赖、初始化及登录前置条件。任何未执行项目都标记 UNTESTED。

| 项目 | 要求与证据 |
|---|---|
| 功能结果 | 参数化重复调用，独立查询或业务回执确认效果；受理成功不等于完成 |
| 参数边界 | 正常、空值、长度边界、非法类型、不同目标；记录预期和实际 |
| 状态隔离 | 多会话或实例不串身份、对象、回调；有状态接口明确生命周期 |
| 中断恢复 | 断连、服务重启、客户端重启、上下文失效后行为可预测 |
| 认证失效 | 返回 AUTH_REQUIRED 或执行明确支持的刷新流程，不无限刷新 |
| 并发与容量 | 在约定负载下测延迟、错误率、资源、背压，不假定无限并发 |
| 长期运行 | 根据业务设持续时间与调用量，测内存、句柄、连接、队列趋势 |
| 版本回归 | 已支持版本逐项验证；未知版本停止不兼容调用并报告 |
| 无 UI 依赖 | 最终调用链不使用点击、截图识别、键鼠或 DOM 事件模拟 |
| 清理 | 关闭连接、释放对象、撤销观测改动；保留原样本和回滚说明 |

## 重试与副作用

给每次业务操作分配 operation_id，但本地 ID 本身不代表服务端支持去重。区分请求未发送、已发送待确认、明确失败和成功。超时或连接中断后的结果可能是 unknown；先查询或对账。没有可靠幂等/去重机制时，副作用操作不自动重发。

对于可安全重试的操作，设置总 deadline、次数上限、指数退避和 jitter，遵循服务端限流提示。失败恢复不应无限递归。取消请求不保证远端操作取消，仍需确认结果。
