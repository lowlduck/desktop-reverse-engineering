# 怎么让这个技能真的被用上

> 这份随技能一起安装，方便装在 `$DSH_HOME/skills/` 之后就地查看。
> 完整说明（实战结论、结构、安装、维护）见仓库 [README](../../README.md)。

## 1. 新会话第一句

最短，只加载：

```
/desktop-reverse-engineering
```

推荐，一次把约束讲完：

```
先加载 desktop-reverse-engineering 技能，按它的开工顺序走。
目标：<软件名> 的 <功能>。Windows，进程名 <PROC>，装我本机，用自己的测试账号，测试对象也是我的。
只要接口/协议，最终不要 UI 自动化。
第一步先侦察：判通道、判壳、找日志和前端资源，结论写进该目标目录的 RESEARCH_PROGRESS.md，
再决定 T1 还是 T2。
```

## 2. 接着上次的活

```
加载 desktop-reverse-engineering，读 <目标目录>\RESEARCH_PROGRESS.md 恢复上下文。
不要重复验证「已确认」，也不要再试「已排除」。下一步是 <具体那件事>。
```

## 3. 确认这次真的加载了

```
你现在加载的是哪个 skill？复述它的「硬规则」第一条。
```

答出「一次只改一个变量」= 真读了；只泛泛说「我会按逆向流程来」= 没加载，让它重载。
也可以看那一轮有没有 `skill` 工具调用记录——有调用才是真加载。

## 4. 为什么要第一句就说

技能目录只暴露 `名字 + description`，正文要模型主动调 `skill` 工具才进来。description 里有触发词，
但口语化的「帮我看看这个 exe 怎么发消息」命中不稳。正文又是普通消息，长任务压缩时可能被裁掉。

| 时机 | 动作 |
|---|---|
| 会话开头 | 点名加载（最稳） |
| 中途被压缩后 | 「重读一下 desktop-reverse-engineering」 |
| 一直有 | `RESEARCH_PROGRESS.md` 兜底，不重载也能续上 |

## 5. 这个包里每个文件干什么

只有 `SKILL.md` 每次进上下文（8 KB）；其余按症状取用，一次任务通常只碰 2~3 份。

**入口**

| 文件 | 作用 |
|---|---|
| `SKILL.md` | 路由入口：交付定义（T0/T1/T2/非交付）、7 步开工顺序、症状→查哪份、10 条硬规则、反模式。加载技能时读的就是它。 |
| `README.md` | 本文件，给人看：三段开场话术 + 这张文件清单。不进推理，零上下文成本。 |

**元数据**

| 文件 | 作用 |
|---|---|
| `agents/openai.yaml` | 宿主界面展示用：显示名「桌面端应用逆向」、一句话简介、默认提示词。 |

**分册（`references/`，按症状取用）**

| 文件 | 作用 | 什么时候读 |
|---|---|---|
| `00-development-guide.md` | 长文附录 3140 行：完整开发指南、两类客户端形态对照、错误码整篇、注入后请求没发出去的 16.1/16.2。正文不绑定产品，产品名只在附录 D。 | 需要整篇判断时；日常不读 |
| `01-goals-evidence.md` | 交付等级、证据标签、路线优先级、壳四分类、时间盒与熔断。 | 不知道先试哪条路 / 遇到壳 |
| `02-observation-routing.md` | 前 30 分钟侦察清单（进程+完整命令行、递归导入表、日志、前端资源）、观测点性价比、通道判定。 | 开工第一步 |
| `03-protocol-contract.md` | `invoke()` 语义、幂等与 operation_id、WS 落地五步、契约字段。 | 抓通一次后固化接口 |
| `04-internal-call-adapters.md` | T2 路线：导出函数 / 业务对象方法 / 本地桥接，核心是「调而不破」。 | 要直接调客户端内部函数 |
| `05-reliability-acceptance.md` | 验收表、支持范围声明、交付形态清单、一键回滚。 | 交付前 |
| `06-credentials-session.md` | 会话代次与冻结材料、三级判定（磁盘/调试接口/内存）、掉线归因、材料复用边界。 | 没登录态 / 跑几小时掉线 / 重登后失效 |
| `07-param-recovery.md` | 前端三路径、信封假设、错误码 A/B/C/D 分层、签名策略。 | 一直报「参数错误」 |
| `08-context-budget.md` | 大输出落盘、切片读法、研究记录写法、压缩后如何恢复。 | 上下文快满 / 忘了试过什么 |
| `09-pitfalls.md` | 方向性陷阱 8 条 + 操作陷阱 7 条 + Windows 工具链坑。 | 卡住之前先看 |
| `10-tooling.md` | 工具选型矩阵与实操：调试器 / hook / 反编译器 / 抓包各自适用面与坑。 | 手上一堆工具不知道开哪个 |
| `11-encrypted-protocol-independence.md` | 把「独立」拆成五阶段（获取/计算/发送/解析/刷新）逐一验证；小错误包、真实游标、去重验收。 | 网络只见加密隧道 / 想把调用移出页面 |
| `12-instrumentation-lifecycle.md` | 采集器生命周期：固定 PID+创建时间、采样预算上限、stop/unload 超时与「属性假关闭」。 | 装/卸 hook、清理超时、崩溃归因 |
| `13-independent-search-case.md` | 脱敏实战案例（2026-10-23~26）：从页面依赖到两页独立请求的完整过程与反例。不含端点、地址、标识、DLL、原始抓包。 | 想知道方法来源和成功边界长什么样 |

**模板（`templates/`，填空即交付）**

| 文件 | 作用 |
|---|---|
| `research-record.md` | `RESEARCH_PROGRESS.md` 四章节：目标与环境、已确认结论（带证据）、已排除方案（带错误码）、下一步。会话被压缩后靠它续命。 |
| `interface-contract.md` | 接口契约：版本、支持平台/架构、T1/T2 路线、不支持范围、材料获取与刷新的分别依赖。 |
| `validation-matrix.md` | 验证矩阵：测试项 × 输入前置 × 预期 × 实际 × 次数耗时 × PASS/FAIL/UNTESTED × 证据路径。 |
| `capture-session.md` | 采样记录：PID+创建时间、模块哈希、UI 入口与内层路由、五阶段依赖、预算与停止条件。放私有目录，公开副本只留脱敏事实。 |
