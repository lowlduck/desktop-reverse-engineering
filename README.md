# Desktop Reverse Engineering Skill

把桌面应用的一个功能研究成**稳定、可复用、可编程的接口**。不限 HTTP，也覆盖 WebSocket / TCP / UDP / IPC 与客户端内部函数调用。

按需加载的工作方法与验证模板，不是现成 SDK。

新增的原生加密链路研究已整理为：

- [分层重建与独立调用](skills/desktop-reverse-engineering/references/11-encrypted-protocol-independence.md)：精确采样边界、业务/传输认证、官方库已知向量、短错误包、真实游标与去重。
- [采集器生命周期](skills/desktop-reverse-engineering/references/12-instrumentation-lifecycle.md)：单一 owner、串行清理、pending 操作、崩溃证据与完成判据。
- [脱敏实战复盘](skills/desktop-reverse-engineering/references/13-independent-search-case.md)：旧会话失效定位、新材料验证及两页独立请求的成功范围与未测项。

这些方法适用于不同桌面应用；实际构建、ABI、场景、协议布局和错误码需重新验证。仓库不分发目标二进制、真实端点、登录材料或抓包。

## 实战结论（先看这 13 条，能省掉一半返工）

> 来自一次完整实战（某电商商家工作台，约 12 小时，✅ = 实跑过）。第 3 列是**别误用成什么**。

| # | 结论 | 实测证据 | 别误用成 |
|:-:|---|---|---|
| 1 | **先找日志，再找网络** | 日志函数入参是明文（只有落盘文件才加密），一次 hook 拿到全部 URL + Body | 「日志加密了就放弃」——加密的只是文件 |
| 2 | **CEF 系别碰系统代理** | 系统代理 / 环境变量 / 策略注册表 / hosts+自签证书 / SSLKEYLOGFILE / IFEO 六种全失败 | 「证书没装对」——整条路线排除 |
| 3 | **虚拟化壳不要破** | `.vmp` 段 + 函数开头随机字节 + 动态工具 attach 即被踢；改边界观察 1 小时出结果 | 「必须破壳」当成唯一出路 |
| 4 | **有完整性校验就别换文件** | 换 3 个 DLL 崩 3 次，内存 patch 长期稳定 | 「崩了 = 我代码写错」——先查校验 |
| 5 | **虚函数用导出 hook 会 0 触发** | 导出 hook 一次没进；patch vtable 正常，只扫前 24 槽 | 「hook 不触发 = 符号找错」 |
| 6 | **会话票据往往不落盘** | Chromium cookies 表里压根没那一行（`is_persistent=0`） | 「DPAPI 解密没写对」——数据不在那 |
| 7 | **内存取票要绑定当前会话** | 一次实验中新旧材料的命中次数不同 | 复制次数能证明有效性；须用来源及真实调用核验 |
| 8 | **只读行为与掉线原因分开** | 只读 API 不直接改认证状态 | 无法被监测、一定不相关；仍需工具行为和时间线证据 |
| 9 | **body 常有信封** | 平铺 7 种组合全报参数错，套 `{data, client}` 立刻成功 | 「字段名不对」——去读 bundle 的传输层 |
| 10 | **错误码是坐标，不是失败信号** | A 类（参数）→ B 类（业务）说明形状已对 | 停在 A 类时去改 ID —— 顺序反了 |
| 11 | **文本走长连接，卡片/文件走 HTTP** | 二进制字符串表里没有「按 ID 发文本」的端点，硬试 HTTP 无解 | 「同一功能同一条通道」 |
| 12 | **UA 三件套不一致最可疑** | 用默认 `Python-urllib` UA 打接口后发生过掉线（因果未定，但嫌疑最大） | 「换个 UA 无所谓」 |
| 13 | **URL/参数后缀要原样** | 媒体地址带 CDN 转码后缀 → 系统错；去掉即成功 | 「多一层后缀应该无所谓」 |

以上表格记录特定环境的经验，不是所有 CEF、壳或客户端的定律。当前执行规范以 skill 入口和对应专题为准。

**三条元结论**：受理 ≠ 完成（要有业务证据）；记录实验变量与对照；设置可调整的时间盒和请求预算。

## 完整开发指南（`references/00-development-guide.md`）

约 3100 行的长文附录，把两轮真实研究**抽离产品**后的通用指南。日常不需要读；遇到下面这些判断时再查：

- **两类客户端形态怎么选路**：前端型与原生单体型的候选路线。原生多层加密也可能拆出独立请求与官方库最小依赖，补充方法见专题 11；不能仅凭架构认定止于 T2。
- **决策与侦察**：目标分层（T0/T1/T2/非交付）、30 分钟侦察表、观测点性价比排序。
- **还原与注入**：序列化入口改写三层次、proto-lite 无 descriptor 时怎么反推 schema、载荷注入的两个致命坑（注入的 `std::string` 被 GC、某些命令类根本不发出去）。
- **验证与交付**：错误码分层（门外 / 进门后业务拒绝 / 成功）、长度指纹核对、成功与失败指纹表、验证矩阵、清理与回滚。
- **避坑与协作**：注入类工具链静默失败清单、Windows 工具链坑、上下文预算纪律、向人求助的边界。

正文不绑定任何产品；产品名与版本只出现在它的「附录 D 证据出处」，用于核对证据，不需要时整段忽略。

## 怎么用（照说就行）

### 1. 新会话第一句

最短，只加载：

```
/desktop-reverse-engineering
```

推荐，一次把约束讲完（省掉后面三轮对齐）：

```
先加载 desktop-reverse-engineering 技能，按它的开工顺序走。
目标：<软件名> 的 <功能>。Windows，进程名 <PROC>，装我本机，用自己的测试账号，测试对象也是我的。
只要接口/协议，最终不要 UI 自动化。
第一步先侦察：判通道、判壳、找日志和前端资源，结论写进该目标目录的 RESEARCH_PROGRESS.md，
再决定 T1 还是 T2。
```

### 2. 接着上次的活

```
加载 desktop-reverse-engineering，读 <目标目录>\RESEARCH_PROGRESS.md 恢复上下文。
不要重复验证「已确认」，也不要再试「已排除」。下一步是 <具体那件事>。
```

### 3. 确认这次真的加载了

```
你现在加载的是哪个 skill？复述它的「硬规则」第一条。
```

答出「一次只改一个变量」= 真读了；只泛泛说「我会按逆向流程来」= 没加载，让它重载。
也可以直接看那一轮有没有 `skill` 工具调用记录——有调用才是真加载，不是凭印象编。

### 4. 为什么第一句就要说

技能目录只暴露 `名字 + description`，正文要模型主动调 `skill` 工具才进来。description 里有触发词
（桌面逆向、抓包还原、接口复现、hook 客户端…），任务描述够典型时会自动命中，但口语化的
「帮我看看这个 exe 怎么发消息」命中不稳。另外正文是普通消息，长任务压缩时可能被裁掉。

| 时机 | 动作 |
|---|---|
| 会话开头 | 点名加载（最稳） |
| 中途被压缩后 | 「重读一下 desktop-reverse-engineering」 |
| 一直有 | `RESEARCH_PROGRESS.md` 兜底，不重载也能续上 |

## 安装

复制 `skills/desktop-reverse-engineering` 到宿主实际扫描的技能根（如 `$DSH_HOME/skills`），保留内部相对结构。

```powershell
if (-not $env:DSH_HOME) { throw '先确认 DSH_HOME' }
$root = Join-Path $env:DSH_HOME 'skills'
New-Item -ItemType Directory -Force $root | Out-Null
Copy-Item './skills/desktop-reverse-engineering' $root -Recurse
```

路径不保证自动生效，先查宿主配置（DSH 看 `skill-filesystem.customSkillDirs`）。支持自定义扫描根的宿主可直接指向本仓库 `skills/`，免复制。刷新目录或开新会话后确认能加载。
